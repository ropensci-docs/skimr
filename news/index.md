- skim() used within a function now prints the data frame name.

## skimr 2.1.0 (2020-01-10)

#### NEW FEATURES

We’ve made
[`to_long()`](https://docs.ropensci.org/skimr/reference/to_long.md)
generic, supporting a more intuitive interface.

- Called on a `skim_df`, it reshapes the output into the V1 long style.
- Called on other tibble-like objects, it first skims then produces the
  long output. You can pass a custom skim function, like
  [`skim_tee()`](https://docs.ropensci.org/skimr/reference/skim.md)

Thanks [@sethlatimer](https://github.com/sethlatimer) for suggesting
this feature.

- Adds more flexibility in the rule width for `skimr::summarize()`.
- More README badges and documentation crosslinks

For most users using `skimr` will not change in terms of visual outputs.
However for users who use `skimr` outputs as part of a larger workflow
the differences are substantial.

#### Breaking changes

##### The `skim_df`

We’ve changed the way data is represented within `skimr` to closer match
expectations. It is now wide by default. This makes piping statistics
much simpler

    skim(iris) |>
      dplyr::filter(numeric.sd > 1)

This means that the old reshaping functions
[`skim_to_wide()`](https://docs.ropensci.org/skimr/reference/deprecated-v1.md)
and
[`skim_to_list()`](https://docs.ropensci.org/skimr/reference/deprecated-v1.md)
are deprecated. The latter is replaced with a reshaping function called
[`partition()`](https://docs.ropensci.org/skimr/reference/partition.md)
that breaks a `skim_df` into a list by data type. Similarly,
[`yank()`](https://docs.ropensci.org/skimr/reference/partition.md) gets
a specific data type from the `skim_df`.
[`to_long()`](https://docs.ropensci.org/skimr/reference/to_long.md) gets
you data that is closest to the format in the old API.

As the above example suggests, columns of summary statistics are
prefixed by `skim_type`. That is, statistics from numeric columns all
begin `numeric.`, those for factors all begin `factor.`, and so on.

##### Rendering

We’ve deprecated support for `pander()` and our `kable()` method.
Instead, we now support `knitr` through the
[`knit_print()`](https://docs.ropensci.org/skimr/reference/knit_print.md)
API. This is much more seamless than before. Having a `skim_df` as the
final object in a code chunk should produce nice results in the majority
of RMarkdown formats.

##### Customizing and extending

We’ve deprecated the previous approach customization. We no longer use
[`skim_format()`](https://docs.ropensci.org/skimr/reference/deprecated-v1.md)
and
[`skim_with()`](https://docs.ropensci.org/skimr/reference/skim_with.md)
no longer depends on a global state. Instead
[`skim_with()`](https://docs.ropensci.org/skimr/reference/skim_with.md)
is now a function factory. Customization creates a new skimming
function.

    my_skim <- skim_with(numeric = sfl(mad = mad))

The fundamental tool for customization is the `sfl` object, a skimmer
function list. It is used within
[`skim_with()`](https://docs.ropensci.org/skimr/reference/skim_with.md)
and also within our new API for adding default functions for new data
types, the generic
[`get_skimmers()`](https://docs.ropensci.org/skimr/reference/get_skimmers.md).

Most of the options set in `skim_format` are now either in function
arguments or print arguments. The former can be updated using
`skim_with`, the latter in a call to
[`print()`](https://docs.ropensci.org/skimr/reference/print.md). In
RMarkdown documents, you can change the number of displayed digits by
adding the `skimr_digits` option to your code chunk.

#### OTHER NEW FEATURES

- Substantial improvements to
  [`summary()`](https://rdrr.io/r/base/summary.html), and it is now
  incorporated into
  [`print()`](https://docs.ropensci.org/skimr/reference/print.md)
  methods.
- [`focus()`](https://docs.ropensci.org/skimr/reference/focus.md) is
  like
  [`dplyr::select()`](https://dplyr.tidyverse.org/reference/select.html),
  but it keeps around the columns `skim_type` and `skim_variable`.
- We are also evaluating the behavior of different `dplyr` verbs to make
  sure that they place nice with `skimr` objects.
- While `skimr` has never really focused on performance, it should do a
  better job on big data sets with lots of different columns.
- New statistic for character variables counting the number of rows that
  are completely made up of white space.
- We now export
  [`skim_without_charts()`](https://docs.ropensci.org/skimr/reference/skim.md)
  as a fallback for when unicode support is not possible.
- By default, `skimr` removes the tibble metadata when generating
  output. On some platforms, this can lead to all output getting
  removed. To disable that behavior, set either `strip_metadata = FALSE`
  when calling print or use `options(skimr_strip_metadata = FALSE)`.

## skimr 1.0.2 (2018-04-04)

CRAN release: 2018-04-02

#### NEW FEATURES

- You can create skimmers with the formula syntax from `rlang`:
  `skim_with(iqr = ~IQR(.x, na.rm = TRUE))`.

#### MAJOR CHANGES

- The median label has been changed to p50 for consistency with the
  previous changes to p0 and p100.

#### MINOR IMPROVEMENTS

- Improvements and corrections to to README and other documentation.
- New vignette showing defaults for skimmers and formats.
- Vector output match data frame output more closely.
- Add minimum required version for testhat.
- Add minimum required version for knitr.

#### BUG FIXES

- You can use
  [`skim_with()`](https://docs.ropensci.org/skimr/reference/skim_with.md)
  to add and remove skimmers at the same time, i.e.
  `skim_with(iqr = IQR, hist = NULL)` works as expected.
- Histograms work when Inf or -Inf are present.
- Change seq( ) parameter to length.out to avoid problems with name
  matching.
- Summary should not display a data frame name of “.” (which occurs when
  piping begins with the data frame).
